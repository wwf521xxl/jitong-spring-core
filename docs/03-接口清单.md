# 03 · 接口清单

所有接口与前端约定保持同路径、同 JSON 字段。  
基础地址：`http://127.0.0.1:8080`。

## 1. 认证

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/login` | 公开 | 工号/姓名/admin + PIN；返回 bootstrap + `token`，并写 Cookie |
| POST | `/api/logout` | 登录 | 递增 `token_version` 并清 Cookie |
| POST | `/api/auth/refresh` | 公开（凭 Cookie） | 用 Refresh Cookie 换新的 Access Token |
| GET | `/api/bootstrap` | 登录 | 首屏聚合数据 |
| GET | `/api/me` | 登录 | 当前员工视图 |
| POST | `/api/change-password` | 登录 | 修改自己的 PIN/密码 |
| GET | `/api/health` | 公开 | 健康检查 |
| GET | `/api/initial-accounts` | 内网 + 开关 | 演示/首次部署账号提示 |

登录请求：

```json
{ "account": "7", "pin": "123456" }
```

登录响应（节选）：

```json
{
  "user": { "id": "E007", "name": "员工07", "isAdmin": false, "canCreateJob": true },
  "employees": [],
  "skills": [],
  "routes": [],
  "jobs": [],
  "records": [],
  "corrections": [],
  "settings": { "duplicateMinutes": 10, "tolerance": 0.05 },
  "token": "eyJhbGciOiJIUzI1NiJ9..."
}
```

同时响应头：

```http
Set-Cookie: jitong_session=...; HttpOnly; SameSite=Lax; Path=/; Max-Age=2592000
```

## 2. 订单与自动报工

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/jobs`、`/api/admin/jobs` | 登录 + 建单权限 | 建单；admin 也不能建单 |
| GET | `/api/jobs/{jobId}/auto-report/options` | 登录 | 当前员工可自动报的工序 |
| POST | `/api/jobs/{jobId}/auto-report` | 登录 | 自动报工；合报工序返回 `group` |
| PATCH | `/api/admin/jobs/{jobId}` | ADMIN | 改订单号/备注/米数 |
| POST | `/api/admin/jobs/{jobId}/void` | ADMIN | 作废 |
| POST | `/api/admin/jobs/{jobId}/complete` | ADMIN 或建单人 | 完成订单 |
| POST | `/api/admin/jobs/{jobId}/groups/{stepNo}/close` | ADMIN 或建单人 | 结束合报 |
| POST | `/api/admin/jobs/{jobId}/groups/{stepNo}/members/{employeeId}/remove` | ADMIN 或建单人 | 移除合报参与人 |

建单：

```json
{ "unit": "m²", "orderNo": "TB20261124001", "remark": "加急", "meters": 48.5, "routeKey": "PHOTO" }
```

规则：

- `unit` ∈ `m² / 件 / 套 / 块`；
- 不传 `line` 时：`m²` → 写真，其他 → 亚克力；
- 不传 `routeKey` 时：写真 → `PHOTO`，亚克力 → `A`；
- 订单号为空自动生成 `TB + yyyyMMdd + 3 位随机数`；
- 建单后把路线复制到 `job_steps`，之后改路线不影响该订单。

自动报工：

```json
{ "stepNo": 3 }
```

`stepNo` 可省略，服务端选当前员工可报的第一道未报工序。

合报工序（`写真过板`、`写真亚克力加工`、`激光切割`）第一次调用会返回：

```json
{
  "group": {
    "id": "G...",
    "stepNo": 3,
    "status": "open",
    "totalQty": 48.5,
    "memberCount": 2,
    "perQty": 24.25,
    "members": [{ "id": "E009", "name": "员工09" }]
  }
}
```

## 3. 报工与冲销

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/records` | 登录 + 工序技能 | 手工报工 |
| POST | `/api/records/{recordId}/corrections` | 记录本人 | 申请冲销 |
| POST | `/api/admin/records/{recordId}/approve` | ADMIN | 确认超量待确认记录 |
| POST | `/api/admin/records/{recordId}/reject` | ADMIN | 驳回待确认记录 |
| POST | `/api/admin/corrections/{correctionId}/approve` | ADMIN | 同意冲销（原记录作废） |
| POST | `/api/admin/corrections/{correctionId}/reject` | ADMIN | 驳回冲销 |
| GET | `/api/photos/{filename}` | 登录 | 现场照片 |

报工请求：

```json
{
  "jobId": "J...",
  "stepNo": 1,
  "qty": 5,
  "unit": "件",
  "note": "",
  "idempotencyKey": "可选的客户端键",
  "source": "scan",
  "deviceId": "android-xxx",
  "photo": "data:image/jpeg;base64,...",
  "forceDuplicate": false
}
```

业务校验顺序：

1. 订单进行中；
2. 工序存在；
3. 员工技能包含该工序；
4. 单位一致；
5. 幂等键是否已存在（存在直接返回原记录）；
6. 10 分钟内同人/同订单/同工序/同数量是否重复（可 `forceDuplicate` 跳过）；
7. 上游完成量与计划量（自动报工跳过上游校验）；
8. 超量则落 `pending`，否则 `valid`。

## 5. 统一错误

```json
{
  "detail": {
    "code": "duplicate",
    "message": "疑似重复报工：刚提交过相同数量，请确认后再试"
  }
}
```

| HTTP | code | 场景 |
| --- | --- | --- |
| 400 | `bad_request` | 参数/单位/数量错误 |
| 400 | `upstream_empty` | 上游未完成 |
| 400 | `steps_incomplete` | 完成订单时仍有工序无有效报工 |
| 401 | `unauthorized` | 未登录/过期 |
| 401 | `bad_credentials` | 工号或 PIN 错误 |
| 403 | `forbidden` | 无权限 |
| 403 | `no_skill` | 技能不包含工序 |
| 404 | `job_not_found` / `step_not_found` / `not_found` | 资源不存在 |
| 409 | `duplicate` | 重复报工 |
| 409 | `order_exists` | 订单号重复 |
| 409 | `job_has_records` | 已有报工仍改米数 |
| 409 | `concurrent_update` | 乐观锁冲突 |
| 429 | `too_many_attempts` | 登录尝试过多 |
