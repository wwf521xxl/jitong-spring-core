# 09 · 生产部署

## 1. 部署组成

```text
Nginx（HTTPS / 同源反向代理）
   │
   ▼
Spring Boot（8080）
   ├─ PostgreSQL（5432）
   ├─ /app/data/photos
   └─ /app/data/backups
```

前端静态文件由 Spring Boot 直接提供，不需要单独部署前端容器。  
Nginx 只负责 HTTPS、域名和反向代理，保证 Cookie 与 `/api` 同源。

## 2. 环境要求

| 组件 | 要求 |
| --- | --- |
| JDK | 21 |
| PostgreSQL | 14+，生产建议 16 |
| Nginx | 1.20+ |
| 内存 | 1 GB 起步，2 GB 更稳 |
| 磁盘 | 系统 + 数据库 + 照片/备份，建议 20 GB 起 |

## 3. 环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `JITONG_DB_URL` | 是 | `jdbc:postgresql://127.0.0.1:5432/jitong` |
| `JITONG_DB_USER` | 是 | 数据库用户 |
| `JITONG_DB_PASSWORD` | 是 | 数据库密码 |
| `JITONG_JWT_SECRET` | 是 | 至少 32 字节的随机字符串 |
| `JITONG_COOKIE_SECURE` | 是 | HTTPS 下设为 `true` |
| `JITONG_SHOW_ACCOUNTS` | 是 | 生产设为 `false` |
| `JITONG_SEED_DEMO` | 是 | 生产设为 `false` |
| `JITONG_ADMIN_PASSWORD` | 是 | 首次启动创建管理员用，首次登录后立即修改 |
| `JITONG_DATA_DIR` | 建议 | 照片和备份目录，默认 `./data` |
| `JITONG_PORT` | 否 | 默认 `8080` |

生成随机密钥：

```bash
openssl rand -base64 48
```

## 4. Docker Compose

仓库根目录：

```bash
cp deploy/.env.example deploy/.env
# 修改 deploy/.env 里的密码和 JWT 密钥
docker compose -f deploy/docker-compose.yml up -d --build
```

默认端口 `8080`，数据库数据在 `postgres-data` 卷，应用数据在 `jitong-data` 卷。

## 5. 裸机部署

### 5.1 构建

```bash
cd springboot-core
./mvnw -DskipTests package
# 产物：target/jitong-spring-core-1.0.0.jar
```

### 5.2 首次启动

```bash
export JITONG_DB_URL='jdbc:postgresql://127.0.0.1:5432/jitong'
export JITONG_DB_USER='jitong'
export JITONG_DB_PASSWORD='强密码'
export JITONG_JWT_SECRET="$(openssl rand -base64 48)"
export JITONG_COOKIE_SECURE='true'
export JITONG_SHOW_ACCOUNTS='false'
export JITONG_SEED_DEMO='false'
export JITONG_ADMIN_PASSWORD='首次登录用的强密码'
export JITONG_DATA_DIR='/var/lib/jitong'

java -jar target/jitong-spring-core-1.0.0.jar
```

首次启动会：

1. Flyway 建表；
2. 如果员工表为空，创建管理员 `admin`（`employee_no=0`）；
3. 写入默认参数 `duplicate_minutes=10`、`tolerance=0.05`。

之后用 `admin` 登录，创建工序、路线、员工和技能授权。

### 5.3 systemd 示例

```ini
[Unit]
Description=Jitong Spring Boot
After=network.target postgresql.service

[Service]
User=jitong
WorkingDirectory=/opt/jitong
EnvironmentFile=/etc/jitong/env
ExecStart=/usr/bin/java -Xms256m -Xmx512m -jar /opt/jitong/jitong-spring-core-1.0.0.jar
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now jitong
```

### 5.4 Nginx

```nginx
server {
    listen 80;
    server_name jitong.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name jitong.example.com;

    ssl_certificate     /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;

    client_max_body_size 5m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
```

Spring 已配置 `server.forward-headers-strategy=framework`，能正确识别外部 HTTPS 和客户端 IP。

## 6. 数据库

### 6.1 建库

```sql
CREATE USER jitong WITH PASSWORD '强密码';
CREATE DATABASE jitong OWNER jitong;
```

### 6.2 数据库变更

Flyway 在应用启动时自动执行 `classpath:db/migration`。  
生产只允许新增迁移脚本，不修改已执行的历史脚本。

### 6.3 备份

```bash
pg_dump -U jitong -h 127.0.0.1 -Fc jitong > /backup/jitong-$(date +%F-%H%M).dump
```

恢复：

```bash
pg_restore -U jitong -h 127.0.0.1 -d jitong --clean --if-exists /backup/jitong-xxx.dump
```

应用内“清空生产数据”也会在 `JITONG_DATA_DIR/backups/` 生成 JSON 备份。

## 7. 发布与回滚

### 发布

1. `pg_dump` 备份；
2. 上传新 jar；
3. 重启服务；
4. 检查 `/api/health` 和登录；
5. 观察错误日志、报工和合报。

### 回滚

1. 停止服务；
2. 换回上一版 jar；
3. 如果新版本执行了不兼容的数据库变更，恢复发布前备份；
4. 启动并检查。

> 生产不建议依赖自动 down migration；备份 + 回退 jar 更可控。

## 8. 监控与日志

- 健康检查：`GET /api/health`；
- Actuator：`/actuator/health`；
- 应用日志：`journalctl -u jitong -f` 或容器日志；
- Nginx 访问日志：`/var/log/nginx/access.log`；
- 建议监控：进程存活、HTTP 5xx、数据库连接数、磁盘剩余空间。
