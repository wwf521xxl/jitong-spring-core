# 06 · 前端对接与联调

## 1. 原则：前端保持原生、无构建

前端是原生 JavaScript，没有构建步骤，所有请求集中在 `frontend/app.js`：

```js
fetch(path, { method, credentials: 'same-origin', ... })
```

它依赖：

- 同源 Cookie `jitong_session`；
- `/api/login` 返回 bootstrap + `token`；
- 写接口返回 bootstrap，前端直接 `applyBootstrap(data)`；
- 错误体 `data.detail.message` / `data.detail.code`；
- 首次加载 `/api/bootstrap`，401 就显示登录页。

后端按这些约定实现，前端不需要 npm、打包或单独部署。

## 2. 静态资源怎么接

`frontend/` 是前端源码目录。`pom.xml` 在构建时把它复制到 `static/`：

```xml
<resource>
  <directory>../frontend</directory>
  <targetPath>static</targetPath>
  <filtering>false</filtering>
</resource>
```

Spring Boot 提供：

- `/`、`/index.html`：`FrontendController` 读取 `static/index.html`，注入：
  ```html
  <script>window.JITONG_MODE = 'server';</script>
  ```
  首页在服务端注入运行模式，前端不需要改入口；
- `/*.js`、`/*.css`、`/vendor/**`、`/icons/**`、`/manifest.webmanifest`、`/sw.js`：Spring 静态资源处理器；
- `/api/*`：Spring Controller。

注意：

- 首页必须 `Cache-Control: no-store`，否则 PWA 更新时容易拿到旧壳；
- `sw.js` 会缓存静态资源，联调时用浏览器“清缓存/硬刷新”；
- `/qr.html` 等辅助页也原样保留。

## 3. 反向代理

生产建议同源部署，Nginx 示例：

```nginx
server {
    listen 443 ssl;
    server_name jitong.example.com;

    ssl_certificate     /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Spring 配置：

```yaml
server:
  forward-headers-strategy: framework
```

这样 `Origin` 校验、`Secure` Cookie、`request.getScheme()` 都能看到真实外部协议。

## 4. 分开部署时

如果前端放在另一个域名：

1. Spring 配置 CORS：
   ```bash
   JITONG_CORS_ORIGINS=https://jitong.example.com
   ```
2. Cookie 改成：
   ```bash
   JITONG_COOKIE_SAME_SITE=None
   JITONG_COOKIE_SECURE=true
   ```
3. 前端 `fetch` 需要 `credentials: 'include'`（当前是 `same-origin`，需要改一行）。

**不推荐**在生产上走这条路；同源反向代理最稳，也不需要改前端。

## 5. 前端接口对照

| 前端调用 | Spring 实现 | 说明 |
| --- | --- | --- |
| `POST /api/login` | `AuthController.login` | 写 Cookie，返回 token |
| `GET /api/bootstrap` | `BootstrapController`（AuthController） | 首屏聚合 |
| `POST /api/records` | `RecordController.createRecord` | 手工报工 |
| `POST /api/jobs/{id}/auto-report` | `JobController.autoReport` | 自动报工/开组 |
| `POST /api/admin/jobs/{id}/groups/{step}/close` | `JobController.closeGroup` | 结束合报 |
| `POST /api/admin/jobs/{id}/complete` | `JobController.completeJob` | 完成订单 |
| `POST /api/admin/records/{id}/approve` | `RecordController.approveRecord` | 审批 |
| `POST /api/records/{id}/corrections` | `RecordController.requestCorrection` | 冲销 |
| `GET /api/initial-accounts` | `InitialAccountsController` | 演示账号 |

### 联调验收

- 浏览器 Network 中 `/api/login` 响应有 `Set-Cookie`；
- 刷新页面仍保持登录；
- 401 时前端回到登录页；
- 写操作返回的 JSON 能直接被 `applyBootstrap` 使用；
- 错误提示显示中文 `detail.message`。

## 7. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 登录成功但刷新后 401 | Cookie 没写入/被代理改写 | 检查 `Set-Cookie`、域名、`Secure`、SameSite |
| 写请求 403 `csrf_origin` | 前后端不同源 | 配 CORS 白名单或改同源代理 |
| 页面未更新 | Service Worker 缓存 | 硬刷新/注销 SW |
| 静态 404 | 没执行 `mvn package` | `frontend/` 未被复制到 `static/` |
| `/api/docs` 404 | springdoc 未加载 | 检查依赖与 Security 放行 |
